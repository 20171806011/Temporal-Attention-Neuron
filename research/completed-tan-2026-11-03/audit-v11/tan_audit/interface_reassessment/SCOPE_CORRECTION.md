# Scope correction to the earlier input-loss phrasing

This note supersedes any broad reading of the version5 phrase “the native input interface loses information.” It preserves the prior constructed pair and all measured outputs.

Use this precise statement:

> The registered P1B transduction can give identical current, novelty, timing and query paths for histories containing multiple low-key events on its rectifier-flat branch while requiring different values. This remains possible after a common primer activates the gate. When novelty is positive, however, the complete event input map is invertible. Within the declared full-presentation/fixed-N and at-most-one-zero-event condition, a valid query also resolves the remaining low event for an unrestricted full-path observer.

Do not extend the claim to all positive-novelty histories, to the raw-array Python API, to M0's raw cache, to all original window-based TAN implementations, or to an original-distribution prevalence estimate. The full-path oracle's mask/history is not supplied to M1. Constant-gate controls can intentionally ignore a delivered channel, and carrier/readout collisions can occur after distinct complete input paths; these are different boundaries.

The all-positive frozen-M1 diagnostic remains poor, so this one front-end ambiguity is not the complete explanation of P1B failure. Neither the collision nor that subgroup result proves population coding necessary or renews a failed baseline equivalence claim. No original result or preregistered label is changed.
