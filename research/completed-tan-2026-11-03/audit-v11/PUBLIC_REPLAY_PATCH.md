# Adapting a disposable public replay

This is an unexecuted preparation guide, not a claim that the sanitized public tree has passed the original end-to-end replay. The complete numerical evidence can be inspected without running simulations.

1. Verify `CURRENT_PUBLIC_SHA256SUMS.txt` before making any changes. Copy the entire public audit directory into a new disposable location. Keep the distributed copy unchanged.
2. For unchanged historical source hashes, obtain the selected source files from the existing public repository at commit `85213f0d417d54e4f48b301ed1c0e4200ef3c421`, rather than replacing expected hashes with whatever happens to be installed. Preserve the `tan_audit/` and sibling `Temporal-Attention-Neuron/` layout. Verify the source files against their entries in `HISTORICAL_SCIENTIFIC_SHA256SUMS.txt`. Later v9/v10/v11 scripts also accept `TAN_REPO_ROOT` for this source location.
3. Review `PUBLIC_COPY_TRANSFORMS.json`. It lists exact old and current hashes for every changed scientific file. Match a hash to its path and purpose before changing a guard. In the disposable copy only, update relocated path references and an affected expected hash only after checking that the corresponding diff is a documented public-copy redaction or path change. Preserve the original expected value beside the replacement in a separate replay adaptation log. Do not edit scientific parameters, input bytes, numeric results, tolerances, exclusions, or analysis logic.
4. Inspect cross-stage dependencies in `noise_preservation_v9/PRIMARY_MANIFEST.json`, `noise_transfer_v10/PRIMARY_MANIFEST.json`, `gate_mechanism_v11/PRIMARY_MANIFEST.json`, the `SOURCE_GUARD.json` records, and each corresponding primary/checker script. Some checks lock earlier scripts, protocols, manifests, and review files, not merely model code. An updated dependency itself changes its hash: record and resolve changes in dependency order. Do not perform a blind global hash substitution or disable assertions. A remaining mismatch is a blocker to be investigated, not grounds to bypass verification.
5. Record the final disposable replay manifest and environment versions separately. Follow the stage-specific commands and output-location rules in `tan_audit/REPRODUCE.md`. Review-only scripts can also write their review outputs, so keep those separate from the distributed evidence.
6. Report comparisons against the unchanged published numerical evidence explicitly. Separate raw-array identity from compressed-container metadata, runtime, source/provenance strings and newly generated review files. A successful adapted replay is a new verification event and must be dated and described as such; it does not retroactively establish byte identity of the edited text with the original preregistration.

Manuscript patches remain proposed and unapplied to the repository. The recorded fragment compilation is not a full release-layout validation. Scientific limitations and original confirmatory decision labels must remain unchanged during a replay.
